# Law-Ebansimsa — UI 디자인 스펙

조례 **입안 협업 IDE**.
담당자가 카테고리별로 의도를 프롬프트로 지시하면, AI가 입안심사 기준·정비 기준에 따라 조례 문장을 작성·수정한다. 작업 종류는 **제정 / 일부개정 / 전부개정** 3가지로 분기되며, 개정은 기존 조례를 불러와 diff 뷰로 작업한다. UI 메타포는 **VS Code**.

> 변경 이력
>
> - v0.1.0 — "완성된 조례안 검토 도구" (폐기)
> - v0.2.0 — "입안 워크스페이스" (8단계 채팅 + 미리보기)
> - v0.3.0 — VS Code 메타포 + 제정/개정 분기 + diff 뷰 + Command Palette

## 1. 제품 정의

### 1.1 한 줄

> 담당자는 조례 카테고리별 의도만 던지면, AI가 표준 구조와 입안·정비 기준에 맞게 조례 문장을 단계적으로 써 내려가는 도구.

### 1.2 핵심 가치

- **구조 강제**: 조례 표준 체계(총칙 → 본칙 → 부칙)를 UI가 강제. AI 환각으로 빠지는 항목 없음
- **단계 잠금**: 1단계씩 완성·확정해야 다음 단계로. 누락된 채로 끝나는 일 방지
- **제정·개정 분기**: 시작 시 작업 종류 선택. 개정은 기존 조례 로드 + diff 메타포로 무엇이 바뀌는지 항상 가시화
- **프롬프트 협업**: 담당자는 "이 조례는 청년 창업 지원이고, 사업비 지원 규정과 위원회 구성이 필요하다"만 말하면 됨. 문장 작성은 AI
- **기준 준수**: 매 작성마다 입안심사 + 정비 기준 위반 여부를 인라인 + 확정 시 정밀 검증
- **타 지자체 참조**: 작성 중 유사 조례를 검색·참조하여 AI 컨텍스트에 활용
- **이력 보존**: 카테고리별 모든 프롬프트·수정 이력 저장 → 의사결정 추적 가능
- **IDE 메타포**: VS Code 같은 다중 패널·탭·split·command palette로 법무 담당자의 다중 참조 작업을 자연스럽게 지원

### 1.3 타겟 사용자

지자체 법무 담당자. 조례 입안 경험은 있으나 매번 표준 구조·기준을 모두 외우긴 어려움. 반복 작업을 줄이고 검토 부담을 낮추고 싶다.

### 1.4 비-목표 (Out of scope, v1)

- 다수 조례 동시 입안 (한 번에 한 프로젝트)
- 모바일 입력
- 조례 외 행정규칙·훈령
- 의회 제출 후 심의 과정 트래킹

## 3. 정보 구조 (IA)

```
/                            (프로젝트 허브 — 진행 중인 작업 + 새 프로젝트 시작)
├─ /new                      (작업 종류 선택: 제정 / 일부개정 / 전부개정)
└─ /draft/[id]               (입안 워크스페이스 — VS Code-like IDE 단일 화면)
   ├─ kind: enact            제정 — 백지에서 시작
   ├─ kind: amend_partial    일부개정 — 기존 조례 로드, 조 단위 변경
   └─ kind: amend_full       전부개정 — 기존 조례 로드, 전체 재작성

   각 kind는 다음 stage를 순회:
   ├─ stage: meta            (1) 제명·제정/개정 사유
   ├─ stage: purpose         (2) 목적 규정
   ├─ stage: definition      (3) 정의 규정
   ├─ stage: scope           (4) 적용 범위·책무
   ├─ stage: main            (5) 본칙 (동적)
   ├─ stage: supplementary   (6) 부칙
   ├─ stage: review          (7) 전체 검토 (매트릭스)
   └─ stage: finalize        (8) 최종안 출력
/wiki                        (위키 — 패널로도 호출 가능)
/criteria                    (심사 기준 관리)
/settings                    (모델·API 키)
```

워크스페이스는 사실상 단일 화면(`/draft/[id]`)에서 stage·뷰·탭만 전환. 라우팅이 아닌 **상태**.

### 3.1 작업 종류 (kind) — 시작 시 분기

`/new`에서 선택 후 워크스페이스 초기화:

| Kind | 시작 상태 | UI 변화 | 위키 근거 |
|------|----------|---------|----------|
| **제정** (enact) | 백지 | Editor에 빈 조례 골격만 표시. 단계 진행하며 채움 | 2편 세부 입안기준 전체 |
| **일부개정** (amend_partial) | 기존 조례 본문 로드 | 좌측에 원본, 우측에 개정안 split. **Diff 뷰가 기본**. 조 단위로 변경/추가/삭제 | 3.2.2 일부개정 방식 |
| **전부개정** (amend_full) | 기존 조례 본문 로드(참고) | 원본 탭 + 신규 작성 탭. Diff는 선택적 | 3.2.3 전부개정 방식 |

#### 개정 시 기존 조례 로드 방법

1. **파일 업로드** (.hwp / .docx / .txt / .md)
2. **타 지자체 검색 후 자기 지자체 조례 가져오기** — 국가법령정보센터 OpenAPI
3. **직접 붙여넣기** — 텍스트 박스

로드된 원본은 **읽기 전용**으로 항상 Editor 좌측에 유지. 모든 변경은 우측 "개정안" 버퍼에서 발생. Diff는 두 버퍼의 차이를 실시간 계산.

## 4. 표준 조례 구조 — 8단계 매핑

위키 `output/ebansimsa/wiki/` 제2편 세부 입안기준을 그대로 단계화.

| # | Stage | 라벨 | 위키 근거 | 필수 |
|---|-------|------|----------|------|
| 1 | `meta` | 제명·제정 사유 | 3.1.2 자치법규의 제명 | 필수 |
| 2 | `purpose` | 목적 규정 | 2.1.2 목적규정 | 필수 |
| 3 | `definition` | 정의 규정 | 2.1.4 정의규정 | 선택(용어 다수 시 권장) |
| 4 | `scope` | 적용 범위·책무 | 2.1.6 / 2.1.7 / 2.1.8 | 선택 |
| 5 | `main` | 본칙 (동적) | 2.2.x 본칙규정 11종 중 선택 | 필수 (1개 이상) |
| 6 | `supplementary` | 부칙 | 2.3.x 부칙규정 7종 | 필수 (시행일은 항상) |
| 7 | `review` | 전체 검토 | 4.1 입안 체크리스트 | 자동 |
| 8 | `finalize` | 최종안 출력 | 3.1.6 작성 형식 | 자동 |

### 4.1 본칙(`main`) 동적 구성

본칙은 조례 성격에 따라 다르므로, AI가 1·2단계 입력(제명·목적)을 분석해 필요한 본칙 항목을 추천한다:

```
AI 추천: 이 조례는 "청년 창업 지원" 성격으로 보입니다. 다음 본칙 항목이 필요합니다:
  ☑ 2.2.7 위원회         (청년창업지원위원회)
  ☑ 2.2.2 보조·출연      (창업자금 지원)
  ☑ 2.2.10 위임·위탁     (사업 위탁 운영)
  ☐ 2.2.11 과태료        (위반 시 — 필요 없을 듯)
  ☐ 2.2.5 기금           (기금 조성 안 한다면 제외)
  [+ 직접 추가]
```

담당자가 체크박스로 확정 → 각 항목이 본칙의 sub-stage가 됨. 본칙 sub-stage 모두 완료해야 6단계로 넘어감.

## 5. 단계 진행 모델

### 5.1 단계 상태

| 상태 | 의미 | 다음 단계 진입 가능? |
|------|------|---------------------|
| `locked` | 이전 단계 미확정으로 잠금 | ✗ |
| `available` | 진입 가능, 미시작 | ✗ (자신 완료 전엔) |
| `in_progress` | 작성 중 | ✗ |
| `validating` | 확정 누르고 정밀 검증 중 | ✗ |
| `confirmed` | 확정 완료, 자유 수정 가능 | ✓ |

### 5.2 단계 확정 흐름

```
[작성 중] ──확정 클릭──▶ [정밀 검증 — 입안·정비 기준 매트릭스 실행]
                              │
                ┌─────────────┴─────────────┐
              통과                          위반
                │                            │
                ▼                            ▼
        [확정 완료]              [위반 목록 표시 + 자동 수정 제안]
              ▲                              │
              └──[담당자가 수용 → 재작성]────┘
```

- 매 단계 확정 시 `pipeline/review/cli.py` 파이프라인을 해당 단계 텍스트에만 적용
- 위반이 있을 때 담당자는 (a) AI 수정 제안 수용 (b) 직접 수정 (c) "이유 있는 예외"로 무시(메모 필수) 중 선택

### 5.3 회귀 (이미 확정된 단계 수정)

- 확정된 단계 클릭 → "수정하시겠습니까? 이후 단계가 영향받을 수 있습니다" 확인
- 수락 시 해당 단계 `in_progress`로, 이후 단계는 자동 `stale` 마크 (확정은 유지하되 경고 표시)
- 이후 단계 재확정 시 stale 해제

### 6.1 Activity Bar (좌측 48px)

세로 아이콘 바. 클릭으로 Primary Sidebar 뷰 전환. 더블 클릭 시 사이드바 토글.

| 아이콘 | 뷰 | 단축키 |
|--------|---|--------|
| 📋 | **단계 (Stages)** — 8단계 트리, 기본 뷰 | `⌘1` |
| 📖 | **위키 (Wiki)** — 입안·정비 기준 위키 트리 | `⌘2` |
| 🔍 | **검색 (Search)** — 현재 조례 + 위키 + 타 지자체 전문 검색 | `⌘⇧F` |
| ⏱ | **이력 (History)** — Git-like 변경 이력 (단계별 timeline) | `⌘3` |
| 🏛 | **타 지자체 (References)** — 검색·로드된 참고 조례 목록 | `⌘4` |
| ⚠ | **문제 (Problems)** — 인라인 힌트·검증 위반 카운트 배지 | `⌘⇧M` |
| ⚙ | **설정 (Settings)** — 모델, API 키, 프로젝트 설정 | `⌘,` |

### 6.2 Primary Sidebar (240px, 좌측)

Activity Bar에서 선택된 뷰가 표시. 폭 조절(드래그) · 접기(`⌘B`) 가능.

**단계 뷰 (기본)** — v0.2.0의 단계 사이드바와 동일:

```
청년 창업 지원 조례  [⏷ 일부개정]
─────────────────────────
▾ 단계
  ● 1. 제명·개정사유      [confirmed]
  ● 2. 목적                [confirmed]
  ◐ 3. 정의 ← 현재
     · 14:02 수정 1개
  ◯ 4. 적용 범위
  ▸ 5. 본칙 (3 sub-stage)
  ◯ 6. 부칙
  ◯ 7. 검토
  ◯ 8. 완성

진행 ━━━━━━━━━━ 38% (3/8)
```

**위키 뷰**: `index.md` 트리. 필터 입력으로 즉시 좁힘. 우클릭 → "현재 단계 컨텍스트에 첨부".

**검색 뷰**: 검색어 + 범위 체크박스(조례 본문 / 위키 / 타 지자체 / 이력). 결과 카드에서 클릭 시 Editor 탭으로 열림.

**이력 뷰**: 단계별·시간순 변경 목록. 항목 클릭 시 그 시점 스냅샷을 Editor 탭으로 열기(diff 비교 가능).

**타 지자체 뷰**: 로드된 참고 조례 칩 목록. 클릭 시 읽기 전용 탭으로 열림. 우클릭 → "AI 컨텍스트에 포함/제외".

**문제 뷰**: 인라인 힌트·검증 위반을 위치별로 묶음. 클릭 시 Editor의 해당 라인으로 점프 (VS Code "Problems" 패널과 동일).

### 6.3 Editor Area (중앙)

VS Code 에디터 영역과 동일한 멀티탭·split·diff 모델.

#### 6.3.1 탭 종류

| 탭 | 내용 | 편집 가능 |
|----|------|----------|
| `개정안.md` (또는 `초안.md`) | 작업 중 조례 본문 | ✓ |
| `원본.md` | 개정 시 로드한 기존 조례 | ✗ (읽기 전용, 회색 배경) |
| `Diff` | 원본 ↔ 개정안 비교 | ✗ (수정은 개정안 탭에서) |
| `위키/§2.1.4-정의규정.md` | 위키 페이지 | ✗ |
| `참고/서울특별시-청년창업지원조례.md` | 타 지자체 조례 | ✗ |
| `검토매트릭스` | Stage 7에서 열림, 매트릭스 뷰 | 인터랙티브 |

탭 우클릭: 닫기 · 다른 탭 모두 닫기 · 오른쪽 패널로 분할 · 고정.

#### 6.3.2 Split View

- 수직 split(좌우)·수평 split(상하) 지원
- 일부개정 모드 진입 시 자동으로 좌(원본) · 우(개정안) 수직 split
- 스크롤 동기화 토글 (조 단위로 정렬)

#### 6.3.3 Diff 뷰

```
┌──────── 원본 ────────┬──────── 개정안 ────────┐
│ 제2조(정의)           │ 제2조(정의)           │
│  1. "청년"이란 만 19  │  1. "청년"이란 19세 이│  ← 행 변경
│     세 이상 ...        │     상 39세 이하인 ... │
│                       │  2. "창업자"란 사업을 │  ← 행 추가
│                       │     등록한 날부터 ... │
│  2. "지원사업"이란    │  3. "지원사업"이란    │
│     ... 말한다.       │     ... 사업을 말한다.│
└───────────────────────┴───────────────────────┘
```

- 행 단위 색: 변경 `--state-progress` 노랑, 추가 `--verdict-pass` 초록, 삭제 `--verdict-fail` 빨강
- 좌측 거터에 `+ / − / ~` 기호 (색맹 대응 P7)
- "조 단위 정렬" 토글: 추가·삭제로 행이 어긋날 때 조 단위로 양쪽을 정렬
- 우상단 토글: `[Inline] [Side-by-Side]` (인라인 diff vs 좌우 분할)
- 개정안 탭에서 변경된 조 위에 부유 액션: `[수용] [되돌리기] [AI에게 이유 물어보기]`

#### 6.3.4 에디터 내부 기능

- 조 단위 시맨틱 폴딩: 제1조, 제2조 단위로 접기·펼치기
- 우측 거터에 minimap(VS Code식)
- 좌측 거터에 단계 배지: 이 조가 어느 단계에서 만들어졌는지 (제명·목적·정의…)
- 텍스트 선택 시 **부유 액션 툴바** 등장 → §7 명령어 버튼

## 7. 명령 시스템 — Command Palette + 부유 액션 + 단계별 동작

VS Code의 "Command Palette + Context Menu + Keyboard Shortcut" 3중 명령 모델을 그대로 채택. 마우스 의존 없이 키보드만으로 전 기능 도달 가능.

### 7.2 부유 액션 툴바 (텍스트 선택 시)

Editor에서 텍스트 선택 → 200ms 지연 후 선택 영역 상단에 부유 툴바:

```
┌────────────────────────────────────────────────┐
│ [✨ 다른 톤] [📏 짧게] [📐 길게] [🔍 근거] [💬 AI에게] │
└────────────────────────────────────────────────┘
"제2조(정의) 이 조례에서 사용하는 용어의 뜻은..."
└─────── 선택 ────────┘
```

- 마지막 버튼 `💬 AI에게`: 우측 채팅 입력란에 "선택: …" 인용 자동 삽입 + 포커스 이동
- Esc / 선택 해제 시 사라짐
- `prefers-reduced-motion`이면 즉시 표시·즉시 사라짐

### 7.3 우클릭 컨텍스트 메뉴

- **조 헤더 우클릭** ("제2조"): 조 이름 변경 · 조 삭제 · 이 조만 AI에게 재작성 · 이 조 검증 · 이 조 위키 근거 보기
- **탭 우클릭**: 닫기 · 다른 탭 모두 닫기 · 우측 분할 · 고정 · 파일 위치 복사
- **사이드바 항목 우클릭**: 위키 항목 → 컨텍스트에 첨부, 참고 조례 → AI 컨텍스트 포함/제외
- **Diff 변경 블록 우클릭**: 이 변경 수용 · 되돌리기 · AI에게 이유 묻기

### 7.4 단계별 자동 동작

각 단계는 별도 페이지가 아니라 **워크스페이스 상태**. 단계 진입 시 다음이 자동 구성:

| Stage | 자동 동작 |
|-------|----------|
| `meta` | Primary Sidebar에 메타 입력 폼 (제명·자치단체·제정/개정 사유). 채팅 컨텍스트 = §3.1.2 |
| `purpose` | Editor에 빈 제1조(목적) 골격 삽입. 컨텍스트 = §2.1.2 |
| `definition` | 빈 제2조(정의) 골격. 컨텍스트 = §2.1.4 + §3.3.1 |
| `scope` | 제3조 적용범위·책무 골격. 컨텍스트 = §2.1.6~8 |
| `main` | **본칙 항목 선택 모달** → 확정 항목들이 sub-stage로 사이드바에 추가. 각 sub-stage 컨텍스트 = 해당 §2.2.x |
| `supplementary` | 부칙 항목 선택 모달 (시행일 기본 포함) → sub-stage. 컨텍스트 = §2.3.x |
| `review` | Editor에 `검토매트릭스` 탭 자동 열기. 부적합 셀 클릭 → 해당 조 점프 |
| `finalize` | Bottom Panel "출력" 탭 자동 표시. 내보내기 형식 선택 + 잠금 옵션 |

#### `main` 본칙 항목 선택 모달

```
┌──────────────────────────────────────────┐
│ 본칙 — 어떤 규정들이 필요한가요?           │
│ AI가 1·2단계를 분석해 추천했습니다.        │
│ ─────────────────────────────────────────│
│ ☑ 위원회 (§2.2.7)        — 청년창업지원위 │
│ ☑ 보조·출연 (§2.2.2)     — 창업자금 보조  │
│ ☑ 권한의 위임·위탁 (§2.2.10)              │
│ ☐ 과태료 (§2.2.11)       — 위반 시 제재   │
│ ☐ 기금 (§2.2.5)                            │
│ ─────────────────────────────────────────│
│ [+ 직접 추가]                              │
│            [선택한 3개로 본칙 구성하기 ▶] │
└──────────────────────────────────────────┘
```

확정 시 단계 트리의 "5. 본칙" 아래에 sub-stage 들여쓰기로 추가. 모두 confirmed 되어야 `supplementary`로 진입.

### 7.5 개정 모드 특별 동작

`kind = amend_partial / amend_full`일 때 추가:

- 진입 시 **기존 조례 로드 모달**: 파일 업로드 / 국가법령정보센터 검색 / 직접 붙여넣기
- 로드 완료 시 `원본.md`와 `개정안.md` 탭 자동 생성, Editor 좌우 split, Diff 탭도 함께
- 사이드바 단계 트리 각 조 옆에 변경 카운터: `제2조 [+3 ~1 -0]` (추가/수정/삭제)
- `amend_partial`: 변경된 조만 출력에 포함되는 미리보기 (개정 조문안 형식, §3.2.2)
- `amend_full`: 전체 재작성 형식, §3.2.3

### 7.6 자동 저장·이력

- 500ms idle 후 자동 저장 (VS Code `files.autoSave: onWindowChange` 유사)
- 매 단계 확정·AI 응답 수용 시 이력 스냅샷 생성
- Activity Bar "⏱ 이력"에서 시간 여행 (Git-like)

- 첨부된 참고 조례는 우측 미리보기 상단 칩으로 표시 (제거 가능)

### 8.2 인라인 힌트 vs 정밀 검증

| 시점 | 검증 종류 | 모델 | 표현 |
|------|----------|------|------|
| AI 응답 생성 후 즉시 | 인라인 힌트 | Haiku, 단일 셀 | 💡 노란색 카드, dismissable |
| 단계 확정 누름 | 정밀 검증 | Sonnet, 전체 기준 매트릭스 | ⚠ 모달 — 위반 목록 + 자동 수정 제안 |
| Stage 7 전체 검토 | 매트릭스 | Sonnet, 전체 조 × 전체 기준 | 매트릭스 뷰 |

### 8.3 이력·타임라인

각 단계마다 우상단 `[📜 이력]` 버튼:

```
14:02 AI: 제2조 1항 작성
14:03 담당자: "지원사업" 추가 요청

```

각 항목 클릭 시 그 시점의 조례 텍스트 미리보기 (시간 여행).

### 8.4 위키 사이드 패널

우측 미리보기 패널을 위키 패널로 전환 가능 (또는 3분할 모드). 단계별로 관련 위키 페이지를 자동 추천.

## 10. 컴포넌트 (이 제품 고유)

### 10.1 StageItem (사이드바 단계)

```
┌─────────────────────┐
│ ● 목적 규정        │  ← confirmed
│ ◐ 정의 규정        │  ← in_progress (현재)
│ ◯ 적용 범위        │  ← available
│ ○ 본칙             │  ← locked
└─────────────────────┘
```

- 높이 40px, 좌측 패딩 16px
- 상태 아이콘 16px, 라벨 text-sm weight-500
- hover: `--bg-sunken`
- 현재 단계: 좌측 3px `--brand-primary` 바 + 배경 `--bg-sunken`
- locked: opacity 0.5, cursor not-allowed
- `aria-current="step"` (현재), `aria-disabled` (locked)

### 10.2 ChatBubble

| Variant | 정렬 | 배경 | 아이콘 |
|---------|------|------|-------|
| user | 우측 | `--bg-chat-user` | 🧑 |
| ai | 좌측 | `--bg-chat-ai` + border | 🤖 |
| system | 중앙 | transparent + italic | (제거 가능) |

- 최대 폭: 컨테이너의 80%
- AI 응답: 하단에 액션 버튼 줄 (수용/부분 수정/재작성)
- 코드(조례 텍스트): 들여쓰기 + monospace + 좌측 4px `--brand-primary` 바

### 10.3 OrdinancePreview (조례 미리보기)

- 조 단위 카드: 각 조마다 ID + "확정/작성중/대기" 배지
- 현재 작성 중 조: 좌측 노란 바 + 부드러운 펄스 (1.5s)
- 확정된 조: 좌측 초록 바
- 빈 조 (아직 작성 안 됨): 점선 placeholder "이 단계가 진행되면 채워집니다"

### 10.4 ValidationDialog (단계 확정 시 검증 결과)

```
┌──────────────────────────────────────┐
│ ⚠ 정의 규정 — 위반 2건 발견           │
│ ──────────────────────────────────── │
│ 1. §3.3.1 용어 사용 기준 위반         │
│   "엔터프라이저"는 외래어. 한자어     │
│   또는 한글로 정비 권장.              │
│   → 제안: "창업자" 사용                │
│   [수용] [무시 (사유 입력)]            │
│                                      │
│ 2. §2.1.4 정의 항 순서                │
│   가나다 순이 아님.                     │
│   → 제안: [재정렬 미리보기]            │
│   [수용] [무시 (사유 입력)]            │
│ ──────────────────────────────────── │
│  [모두 수용]  [모두 무시]  [돌아가기] │
└──────────────────────────────────────┘
```

- "무시" 선택 시 사유 입력 강제 (이력에 기록)
- 모두 수용·돌아가기 외에는 모달 닫기 불가 (의도적 마찰)

## 14. 백엔드 연동 매핑

| 최종 출력 | 마크다운 → HWP/DOCX/PDF 변환기 (신규 `pipeline/export/`) |
